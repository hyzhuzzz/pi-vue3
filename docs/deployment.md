# 部署与嵌入

## 第一版运行边界

当前设计为本机单可信使用者、单 Node 进程与本地数据目录。默认监听 `127.0.0.1`。前端是浏览器静态资源；Pi 服务必须由 Node.js 持续运行。

需要面向真实多用户或通过网络开放时，先接入现有产品的认证、会话归属和业务权限校验。Origin/Host 限制不能代替用户鉴权。

## 发布流程

在与目标服务器兼容的环境中安装锁定依赖并构建：

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
```

发布包需要包含构建后的服务端、前端静态文件、共享协议包、生产运行依赖、Skill 目录以及配置示例。内网部署应在构建环境准备好依赖，避免到客户服务器上再联网安装。

前端与服务端保持独立构建边界。可以由 Nginx 提供前端并转发 `/api/assistant`，也可以使用服务端提供构建后的前端静态资源。

在仓库根目录构建后启动服务：

```sh
pnpm --filter @pi-vue3/agent-server start
```

服务默认监听 `http://127.0.0.1:3001`。生产进程应由 systemd 或已有部署平台管理，使用专用运行账号，并通过环境变量或服务器侧配置提供凭据。

## 数据与配置

- `.env`：仅服务端读取的本地配置，包含模型密钥，不进入 Git。
- `.data/`：默认本地会话与任务数据，不进入 Git。
- `skills/`：由研发维护并随产品版本发布的受控资源目录。

备份时保留完整数据目录，包含 Pi 会话文件和产品元数据。升级前先停止服务并备份，避免在写入中复制不一致的文件。服务重启不会自动继续未完成的模型请求。

## 嵌入其他应用

1. 在 Vue3 根布局挂载助手组件，配置服务地址和可选页面上下文。
2. 按需通过应用已有的后端或网关转发 REST/SSE，并接入真实登录态与会话归属。
3. 在服务端提供模型配置；密钥不经浏览器传输。
4. 按应用需要接入日志、用量与额度管理。
5. 显式注册工具与 Skills；工具调用的权限、数据范围和业务校验由应用服务负责。

SSE 反向代理应关闭响应缓冲，并为长连接设置合适的空闲超时。不要因浏览器重连而重发生成请求。
